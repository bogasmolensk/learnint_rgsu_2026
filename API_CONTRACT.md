# API контракт: Equipment Request Service

## Общие правила
- Все ответы в формате JSON (Content-Type: application/json).
- Даты во всех запросах и ответах — ISO 8601 в UTC, формат: 2026-10-12T15:30:00Z.
- Аутентификация: заголовок Authorization (появится на след. неделях).
  Пока пользователь определяется тестовыми данными / заголовком X-User-Id для демо.
- Ошибки возвращаются в виде: { "error": "CODE", "message": "текст" } с соответствующим HTTP-статусом.

## Разделение полей (клиент и сервер)
- КЛИЕНТ передаёт (в теле запроса): equipment_name, quantity, justification,
(при отклонении) comment.
- СЕРВЕР назначает сам, клиент НЕ может их прислать: id, author_id, status,
decision_comment (кроме случая отклонения), created_at, updated_at, version.
Любая попытка прислать серверное поле в запросе отклоняется (400).

## Таблица операций

| # | Операция | HTTP | URL | Тело запроса (клиент) | Успешный ответ | Ошибки |
|---|---|---|---|---|---|---|
| 1 | Создание заявки | POST | `/api/v1/requests` | `{equipment_name, quantity, justification}` | 201 + карточка (DRAFT) | 400, 401, 403 |
| 2 | Чтение одной | GET | `/api/v1/requests/{id}` | — | 200 + полная карточка | 401, 403, 404 |
| 3 | Список заявок | GET | `/api/v1/requests?scope=&status=&from=&to=&page=&size=` | — | 200 + массив кратких карточек | 401 |
| 4 | Редактирование | PATCH | `/api/v1/requests/{id}` | `{equipment_name?, quantity?, justification?}` | 200 + обновлённая карточка | 400, 401, 403, 404, 409 |
| 5 | Отправка на рассмотрение | POST | `/api/v1/requests/{id}/submit` | — | 200 + карточка (UNDER_REVIEW) | 401, 403, 404, 409 |
| 6 | Отмена | POST | `/api/v1/requests/{id}/cancel` | — | 200 + карточка (CANCELLED) | 401, 403, 404, 409 |
| 7 | Одобрение | POST | `/api/v1/requests/{id}/approve` | — | 200 + карточка (APPROVED) | 401, 403, 404, 409 |
| 8 | Отклонение | POST | `/api/v1/requests/{id}/reject` | `{comment}` (обязательно непустое) | 200 + карточка (REJECTED) | 400, 401, 403, 404, 409 |
| 9 | История | GET | `/api/v1/requests/{id}/history` | — | 200 + массив записей истории | 401, 403, 404 |

Семантика scope (разделение по ролям, строка 3 таблицы): для роли «Сотрудник» список всегда фильтруется по автору — возвращаются только его заявки,
параметр scope игнорируется (чужие заявки сотрудник не видит и не может запросить, это не 403, а фильтрация на уровне запроса).
Для роли «Ответственный» scope принимает значения: all (все заявки), mine (его собственные как автора), pending (статус «На рассмотрении», автор — не он, то есть очередь на его решение). 
Параметры from/to — диапазон дат создания в ISO 8601 UTC.

`400` = невалидные данные / пустой комментарий;
`401` = не авторизован; `403` = нет прав (не автор / не ответственный / ответственный трогает свою заявку);
`404` = заявка не найдена; `409` = переход/редактирование невозможны в текущем статусе (конфликт).

## Примеры JSON

### POST /api/v1/requests — создание
Запрос:
```json
{ "equipment_name": "Монитор 27\"", "quantity": 2, "justification": "Для нового сотрудника" }
```
Ответ 201:
```json
{
  "id": 1,
  "author_id": 1,
  "equipment_name": "Монитор 27\"",
  "quantity": 2,
  "justification": "Для нового сотрудника",
  "status": "DRAFT",
  "decision_comment": null,
  "created_at": "2026-10-13T12:37:00Z",
  "updated_at": "2026-10-13T12:37:00Z",
  "version": 0
}
```

### POST /api/v1/requests/1/reject — отклонение (комментарий обязателен)
Запрос:
```json
{ "comment": "Недостаточно обоснования, уточните задачу" }
```
Ответ 200:
```json
{ "id": 1, "status": "REJECTED", "decision_comment": "Недостаточно обоснования, уточните задачу", "version": 1 }
```

### GET /api/v1/requests/1/history — история (event-log: каждый переход отдельной строкой)
Ответ 200:
```json
[
  { "changed_by": 1, "previous_status": null,           "new_status": "DRAFT",        "comment": null,                          "created_at": "2026-10-13T12:37:00Z" },
  { "changed_by": 1, "previous_status": "DRAFT",        "new_status": "UNDER_REVIEW", "comment": null,                          "created_at": "2026-10-13T12:40:00Z" },
  { "changed_by": 2, "previous_status": "UNDER_REVIEW", "new_status": "REJECTED",     "comment": "Недостаточно обоснования",    "created_at": "2026-10-13T13:00:00Z" }
]
```


### Ошибка 409 — попытка редактировать отправленную заявку
Ответ:
```json
{ "error": "CONFLICT", "message": "Редактирование запрещено: заявка не в статусе DRAFT" }
```
